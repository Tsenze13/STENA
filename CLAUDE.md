# СТЕНА — правила работы и карта кода

## Как мы работаем
- Отвечать по-русски, просто, без жаргона. Автор часто пишет голосом — сообщения бывают сумбурными, это нормально.
- Автор не программист: код пишет Claude, автор решает, что делать, и тестирует.
- Порядок: сначала **бета** (папка `beta/` на сайте), автор проверяет, потом слияние в основную версию.
- Коммитим только после того, как проходят тесты (`python3 tests/smoke.py`).
- Версии: `0.1`, `0.2`… бета — `0.2-бета`. Номер в `src/main.js` (`VERSION`).
- Концепция и сюжет: `docs/concept.md`. Новое решение автора по сюжету или механикам — записывать туда.

## Как устроено
Браузерная 3D-игра от первого лица на Three.js. Сборки нет: `index.html` грузит ES-модули из `src/`,
Three.js лежит в `vendor/three.module.min.js` (r170). Сайт — GitHub Pages из ветки `main`, корень репозитория.
Все текстуры и звуки процедурные (canvas и WebAudio), файлов-ассетов нет.

## Правила кода
- Новый интерактивный объект: меш с `userData.act = 'имя'` в `W.acts` + подсказка в `promptFor` и действие в `interact` (main.js).
- Новая стена — коллайдер `col(x0,x1,z0,z1, on?)` в world.js, иначе сквозь неё можно пройти.
- Свет — только через лампы и группы (`L.setGroup`), не добавлять PointLight на каждую лампу: дорого.
- Мелкие детали — через `makeBatch` (world.js `B.add`), а не отдельными мешами: иначе сотни вызовов отрисовки.
- Изменения питания — только через `G.set(ключ, значение)`: там проверка перегрузки и обновление всего остального.

## Тесты
`python3 tests/smoke.py [папка]` — с папкой ещё сохраняет скриншоты. Рендер в тесте программный и медленный,
поэтому тест ставит `window.__st.paused = true` и крутит игру через `__st.step(сек)`.
В песочнице npm и CDN закрыты; Three.js брать из GitHub (`mrdoob/three.js`, папка `build/`).
